# مجتمع بلس — الدليل الهندسي (v2.3)

## 1. البناء والتشغيل
- **التطوير:** `node server/server.js` يقدّم الملفات الأصلية مباشرة (SQLite).
- **الإنتاج:** `npm run build` ثم `WEB_ROOT=dist node server/server.js`، أو `docker compose up` (البناء متعدد المراحل داخل الصورة).
- الخادم يقدّم `.br` أو `.gz` حسب المتصفح، وتخزين دائم (`immutable`) للملفات المُبصمة، و`no-cache` لـ HTML وService Worker، وتلميحات `Link: preload`.

## 2. السجلات والأخطاء
- كل طلب يحمل `X-Request-Id` (يُقبل من البوابة أو يُولّد)، ويظهر في السجل وفي رد الخطأ.
- سجلات JSON منظمة (`LOG_LEVEL`, `LOG_FORMAT=pretty`, `LOG_REQUESTS=1`).
- أخطاء الواجهة تُرسل إلى `/api/client-errors` وتُجمّع ببصمة، ويمكن تمريرها لأي خدمة خارجية عبر `ERROR_WEBHOOK_URL` (متوافق مع GlitchTip/Sentry webhooks).
- أي شاشة تتعطل تعرض بطاقة استعادة بدل صفحة بيضاء، ويُبلَّغ الخطأ تلقائياً.

## 3. قاعدة البيانات
- ترحيلات مرقّمة في `server/migrations` (‏001 أساس، 002 فهارس، 003 أمان، 004 تشغيل، 005 بحث pg_trgm)، كل واحدة لها `up` و`down`.
- مستودعات (`server/repos`) تعزل SQL الجلسات والمستخدمين عن منطق الخدمات.
- نسخة قراءة: `DATABASE_REPLICA_URL` تُستخدم تلقائياً لاستعلامات الخلاصة والبحث والرائج، مع رجوع للأساسية عند الفشل.
- PgBouncer بوضع transaction pooling في `docker-compose.yml`.
- نسخ احتياطي يومي مشفّر AES-256 (`ops/backup/backup.sh`) واختبار استعادة (`restore-test.sh`). **تم اختبارهما فعلياً** على PostgreSQL 17 (‏200 مستخدم، 2,000 منشور).

## 4. الأمان
| الميزة | التفاصيل |
|---|---|
| التحقق بخطوتين | TOTP قياسي (RFC 6238) مع QR، حماية من إعادة استخدام الرمز، 10 رموز احتياطية مُجزّأة تُستخدم مرة واحدة |
| مفاتيح المرور | WebAuthn (ES256/RS256) بدون مكتبات خارجية، تحدٍّ صالح 5 دقائق ولمرة واحدة، كشف المفاتيح المستنسخة |
| الجلسات | عرض الأجهزة، آخر نشاط، خروج من جهاز أو من الكل |
| أجهزة جديدة | إشعار عند الدخول من جهاز أو شبكة غير معروفة |
| سجل التدقيق | سلسلة بصمات SHA-256؛ أي تعديل أو حذف يُكتشف من `/api/admin/audit/verify` |
| الأسرار | كل سر يُقرأ من `NAME` أو `NAME_FILE`، و`NAME_PREVIOUS` لفترة التدوير |
| التبعيات | Dependabot أسبوعياً، وفحص Trivy للصورة في CI |

## 5. الأداء
- Service Worker: فتح فوري للزيارات المتكررة، وواجهة تعمل دون اتصال (تم اختباره بقطع الشبكة).
- تحميل كسول للصور، ووضع توفير البيانات، و`content-visibility` للقوائم الطويلة.
- قياس الأداء الحقيقي (LCP, FCP, CLS, INP, TTFB) يظهر في صفحة حالة النظام.
- التخزين المؤقت يمنع «تدافع» الطلبات المتزامنة (single-flight)، والتحقق من صلاحية الرؤية صار دفعة واحدة بدل استعلام لكل منشور.

### نتائج اختبار الحمل (خادم واحد، PostgreSQL 17، ‏200 مستخدم و2,000 منشور، 100 اتصال متزامن)
| المسار | قبل | بعد |
|---|---|---|
| الخلاصة المخصصة | 438 طلب/ث · p99 ‏5,849ms | **1,621 طلب/ث · p99 ‏92ms** |
| خلاصة المتابَعين | 1,326 طلب/ث · p99 ‏88ms | 1,747 طلب/ث · p99 ‏80ms |
| البحث | 173 طلب/ث · p50 ‏565ms | **484 طلب/ث · p50 ‏202ms** |
| فحص الصحة | 31,096 طلب/ث | 25,287 طلب/ث |

عند 1,000 اتصال متزامن: **صفر أخطاء**، والخلاصة 1,646 طلب/ث بزمن p99 ‏678ms. السقف الحالي هو نواة معالج واحدة؛ التوسع الأفقي في المرحلة 48.

## 7. أعلام الميزات
`/api/flags` يقيّم الأعلام لكل مستخدم: تشغيل/إيقاف، نسبة تدريجية (حسب بصمة ثابتة للمستخدم)، وقائمة سماح. تُدار من صفحة حالة النظام.
