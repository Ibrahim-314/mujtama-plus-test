# 07 — سياسة الانتقال (Migration Policy)

> **مسودة داخلية — غير معتمدة وليست إعلانًا للأعضاء.** هذه الوثيقة **لا تتضمن نسبة تحويل ولا وعدًا بأي تحويل**. الأرصدة الداخلية ليست التزامًا ماليًا على المشروع.
> الموقف: «مكافآت الآن، وتوكن مستقبلًا». المصادر: [00-README](00-README.md).

## 1. المعلومات المؤكدة
- الرصيد الداخلي معرّف في الكود بأنه «رصيد داخل التطبيق فقط — ليس عملة على أي بلوكشين، ولا يُسحب ولا يُباع» (`mjt.js`)، و«ليس له قيمة نقدية، ولا يُسحب ولا يُباع ولا يُحوَّل» (`mjt-rewards.js`).
- جزء من الأرصدة القائمة جاء من مسارات قديمة بمبالغ ثابتة (تعدين 5/يوم، دخول 1/يوم، تحويل نقاط 1:1، رصيد تجربة المالك) — أي أن الرصيد **لا يعكس بالضرورة مساهمة متكافئة** بين الأعضاء.
- الخطة السابقة (`docs/MJT-PI-TESTNET-PLAN.md`، غير منفّذة) لاحظت أن دقة الوحدات (7 منازل) تطابق أصول Pi، وأن الربط بالرصيد الداخلي قرار مفتوح على Testnet — **هذه الوثيقة لا تعتمد أي ربط لأي Mainnet**.
- لا أرقام إنتاج متاحة عن حجم الأرصدة أو توزيعها.

## 2. السيناريوهات الثلاثة

### السيناريو 1 — يبقى MJT داخليًا فقط (لا توكن)
| | |
|---|---|
| **المزايا** | أبسط وأقل مخاطرة؛ لا تعرّض تنظيمي للأصول المشفرة؛ لا اعتماد على Pi Launchpad؛ مرونة كاملة في القواعد |
| **المخاطر** | توقعات بعض الأعضاء بأن MJT «سيصبح عملة» — تُدار بالتواصل الواضح |
| **المتطلبات التقنية** | لا شيء جديد؛ استمرار المراحل 4–6 |
| **أثر على الأعضاء** | لا تغيير؛ الرصيد يبقى للمكافآت والخدمات داخل التطبيق |
| **الأثر الاقتصادي** | المشكلة الأساسية (التراكم بلا استخدام) تبقى ويجب حلها داخليًا في كل الأحوال |
| **الأثر القانوني** | الأدنى؛ الرصيد نقاط ولاء داخلية (يُؤكد برأي قانوني) |

### السيناريو 2 — توكن مستقل **دون** تحويل الأرصدة القديمة
| | |
|---|---|
| **المزايا** | فصل نظيف؛ التوكن يبدأ بقواعد جديدة ومعروض مقفل؛ لا يرث تضخم المسارات القديمة؛ لا التزام ضمني تجاه الأرصدة |
| **المخاطر** | خيبة أمل بعض حاملي الرصيد الداخلي؛ لبس في الأسماء (MJT الداخلي مقابل التوكن) |
| **المتطلبات التقنية** | وحدة توكن معزولة (03)؛ لا جسر للدفتر الداخلي؛ اسم/رمز مختلف أو تمييز واضح |
| **أثر على الأعضاء** | الرصيد الداخلي يستمر كما هو للمكافآت والخدمات؛ التوكن يُكتسب فقط عبر Launchpad أو مكافآت جديدة بقواعد جديدة |
| **الأثر الاقتصادي** | لا ضغط بيع من أرصدة تاريخية؛ تقدير المعروض أنظف |
| **الأثر القانوني** | أوضح: لا يوجد ادعاء بأن الرصيد القديم كان «حقًا» في توكن |

### السيناريو 3 — تحويل اختياري مستقبلي بشروط معلنة ومراجعة مستقلة
| | |
|---|---|
| **المزايا** | يعترف بنشاط الأعضاء السابق؛ قد يعزز الولاء |
| **المخاطر** | **الأعلى**: قد يُفسَّر بأثر رجعي كوعد، ويحوّل الرصيد إلى ما يشبه حقًا ماليًا؛ يرث تضخم المسارات القديمة؛ مزارع حسابات تاريخية؛ نزاعات حول الإنصاف؛ ضغط بيع |
| **المتطلبات التقنية** | لقطة (snapshot) مدققة للأرصدة؛ استبعاد/تقييد مصادر غير مرتبطة بالمساهمة (قرار)؛ KYC وربط محفظة؛ سقف لكل عضو؛ مطابقة كاملة للدفتر (`verify()`)؛ اقتطاع من فئة المجتمع (لا معروض إضافي) |
| **أثر على الأعضاء** | اختياري؛ شروط تُعلن مسبقًا وبوضوح؛ لا أحد يُجبر؛ قد لا يستحق كل رصيد |
| **الأثر الاقتصادي** | يجب أن يأتي من حصة المجتمع المحددة مسبقًا، فيقلّص المكافآت المستقبلية |
| **الأثر القانوني** | يحتاج رأيًا قانونيًا ومراجعة مستقلة؛ يُفضّل عدم الإعلان عنه أصلًا قبل اكتمال الشروط |

**لا نسبة تحويل في أي سيناريو.** إن اختير السيناريو 3 يومًا ما، تُحدَّد النسبة بطريقة منشورة بعد مراجعة مستقلة، وقد تكون مختلفة حسب مصدر الرصيد، وقد يكون الجواب «لا تحويل» لبعض المصادر.

## 3. ضمانات تنطبق على كل السيناريوهات
1. لا وعد اليوم بأي تحويل، ولا تلميح إليه في واجهة التطبيق أو المساعد أو المحتوى.
2. الرصيد الداخلي لا يُحذف ولا يُقلّص بسبب قرار التوكن (لا مساس ببيانات الأعضاء).
3. لا ربط تقني تلقائي بين الدفتر الداخلي وأي توكن.
4. الأرصدة الداخلية ليست التزامًا ماليًا على المشروع.

## 4. الافتراضات
أن الأعضاء قد يتوقعون التحويل (لا بيانات عن ذلك؛ يمكن قياسه لاحقًا من الأسئلة الواردة).

## 5. التوصيات
- **الأساس: السيناريو 1 الآن**، والتصميم المستقبلي مبني على **السيناريو 2**.
- السيناريو 3 يُبقى خيارًا نظريًا فقط، لا يُذكر للأعضاء، ولا يُدرس إلا بعد إطلاق توكن مستقل ناجح ورأي قانوني.
- مراجعة نصوص التطبيق الحالية للتأكد أن لا شيء يوحي بالتحويل (مثل `stageNote` الذي يذكر «ربطه بشبكة Pi التجريبية مرحلة لاحقة») — تعديل نصي محتمل في مرحلة لاحقة بموافقة.

## 6. قرارات تحتاج موافقة صاحب المشروع
1. اعتماد السيناريو 1 الآن و2 مستقبلًا.
2. هل يُعدَّل نص `stageNote` في `mjt.js` لإزالة أي إيحاء بالربط مع Pi؟ (تغيير كود — ليس ضمن هذه المرحلة).
3. نص رسمي قصير للرد على سؤال «هل سيتحول رصيدي؟» (مقترح: «MJT رصيد مكافآت داخلي، ولا يوجد أي وعد بتحويله»).
