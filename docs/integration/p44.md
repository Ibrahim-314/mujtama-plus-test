# Phase 44 — Personalization «المظهر والتخصيص» (branch p44, base 978ed28 / v2.14.0)

Free for everyone. Migration **027_prefs** (additive: `user_prefs` + 1 index). Version bump to 2.17.0 is the integrator's.

## Server
- `server/services/prefs.js` + `server/lib/prefs-lib.js` (catalogue, `ui` validator, pure-Node PNG icons, manifest).
- `user_prefs (user_id, ns, key, value JSON TEXT, updated_at)`, PK (user_id, ns, key). Namespace `ui` is strict
  (`theme` system|light|dark, `palette` violet|ocean|forest|sunset|rose|gold|graphite, `oled` bool, `density` comfortable|compact,
  `nav` permutation of home/explore/communities/notifications/me, `icon` classic|ocean|forest|sunset|rose|gold|midnight, `sync` bool).
  Other namespaces are free-form JSON (≤4 KB per value, ≤64 keys per ns, ≤16 ns) for later phases; **`a11y` is reserved** (phase 43 table).
- `GET /api/prefs[?ns=a,b][&rev=]` → `{prefs:{ns:{k:v}}, updatedAt, rev, syncedAt}` (or `{rev, unchanged:true}`).
  `PUT /api/prefs {ns, values:{k:v|null}}` or `{prefs:{ns:{…}}}` (null deletes; whole batch validated first; errors 400
  `bad_pref|bad_key|bad_namespace|reserved_namespace|too_many`, 413 `pref_too_large`). `DELETE /api/prefs?ns=` resets one namespace.
  Last write wins per key (server time); each write sends realtime `"prefs" {rev}` to the user's other sessions.
- Public: `GET /api/prefs/catalog`, `GET /api/prefs/icons/<id>-<180|192|512>.png` (immutable), `GET /api/prefs/manifest.webmanifest?icon=<id>`.
- Compliance: `user_prefs` added to `DATA_MAP` (purpose personalization, erase delete).

## Client
- Lazy chunk **`prefs`** (`prefs-ui.js`): `#/settings/appearance` (entry card on `#/settings`), live preview card (focus/hover a
  swatch previews it in the card; a tap applies app-wide; «تراجع» / defaults), mode + OLED, palettes, density, nav ↑/↓, app icon, sync toggle.
- Mode keeps the existing `data-theme` attribute (system/light/dark) so every `[data-theme=dark]` rule still applies; colour themes,
  OLED and density are CSS custom properties generated in the chunk and exposed as `html[data-palette|data-oled|data-density]`.
  Deviation from "keyed by data-theme": palettes are orthogonal to light/dark, so they get their own attribute.
- Early apply: the chunk caches the generated CSS in `localStorage["mp.ui"]`; `chunks.js` injects it before first render (one line).
  Nav order paints via CSS `order`, then the chunk reorders the DOM so focus order matches. `window.MPPrefs` = {get,set,pull,apply,css}.
- Icons: the chunk swaps `<link rel=manifest|apple-touch-icon|icon>`; the home-screen icon changes when the app is (re)added (OS limitation).
