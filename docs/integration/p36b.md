# Phase 36b (Pi App Studio) — integration notes

Branch `p36b-appstudio` (from tag `v2.9.0`). No migration, no new dependency, no new paid service. Full contract: `docs/PI.md`
(sections "Safety rules", "Client (36b)", "HTTP headers (36b)", "Pi App Studio domain validation").

## What changed
1. **Domain validation file** — `public/pi-app-validation.txt` (44 bytes, no newline) → copied verbatim by `tools/build.mjs`
   (new generic `public/` → `dist/` copy step) → served by the ordinary static handler at `/pi-app-validation.txt`
   (`text/plain; charset=utf-8`, never compressed, never the SPA fallback). Guarded by `.editorconfig`, `.gitattributes`
   (`-text`) and a build check that fails on leading/trailing whitespace. Dockerfile.railway needs nothing (`COPY . .` +
   `COPY --from=build /src/dist/ dist/`; `.dockerignore` does not exclude `public/`).
2. **Pi sign-in via App Studio** (`server/services/pi.js`): `POST /api/pi/auth` exchanges the accessToken server-side with
   `PI_APPSTUDIO_URL` (default `https://backend.appstudio-u7cm9zhmha0ruwv8.piappengine.com/pi/auth/v1/login`) and trusts only the
   returned `user.uid/username`; then the unchanged needsLink / `link:true` / session flow. `sessionToken` is discarded.
   Non-200 → 401 `pi_invalid` (Arabic); network error / bad 200 → 502 `pi_upstream`. One exchange per token (in-memory sha256 cache,
   10 min). Legacy `POST /api/auth/pi` (users.js) now uses the same `ctx.services.pi.verify`.
   New `PI_AUTH_ENABLED` (default **on**) gates sign-in/linking; payments stay gated by `PI_ENABLED` + `PI_API_KEY`.
   New `GET /api/pi/link` → `{linked, piUsername, network}` (Settings uses it, works with payments off).
   `GET /api/pi/config` → `{enabled, authEnabled, network, sandbox, appId?}`.
3. **Client**: `index.html` `<head>` has `<script src="https://sdk.minepi.com/pi-sdk.js"></script>`; `pi-adapter.js` →
   `await Pi.init({version:"2.0"})` (no sandbox), scopes `["username","payments"]`, resolves `{accessToken}` only; `pi-ui.js`
   shows «الدخول بحساب Pi» + the Settings card when `authEnabled`, wallet/admin links and pay buttons only when `enabled`.
4. **Headers** (`server/lib/http.js`): CSP rebuilt (`buildCsp`) — `script-src 'self' https://sdk.minepi.com` + per-file sha256 of
   inline `<script>` blocks (no `'unsafe-inline'`), `connect-src 'self' https://api.minepi.com https://socialchain.app`,
   `frame-src 'self' https://sdk.minepi.com`, `object-src 'none'`, `base-uri 'self'`,
   `frame-ancestors 'self' https://*.pinet.com https://*.minepi.com` (+ optional `CSP_FRAME_ANCESTORS_EXTRA`).
   **X-Frame-Options removed.** Session cookie: `HttpOnly; SameSite=None; Secure` in production, `HttpOnly; SameSite=Lax` on http.
   CSRF (`server/server.js`): new route option `{ piLogin: true }` exempts `POST /api/pi/auth` and `POST /api/auth/pi` from the
   `X-Requested-With` check; `/api/pi/auth` with `link:true` still requires the header (handler-level check via `req.csrfOk`).
5. **Inline handlers removed** (required by the CSP): 11 `onclick="…"` + 2 `href="javascript:history.back()"` in app.js, v12.js,
   community-ui.js, content-ui.js, identity-ui.js, integrity-ui.js, notify-ui.js, security-ui.js → `data-ui="close-sheet|back|compose|route|reload"`,
   handled by one delegated capture listener in `platform.js`. **Any branch merged later that adds `onclick="…"` markup or a
   `javascript:` URL will silently not work under the new CSP — convert it to `data-ui` (or addEventListener).**

## Operator / integrator must know
- **Performance**: the Pi SDK tag is render-blocking in `<head>` for every visitor (≈1.1 MB unminified from sdk.minepi.com, checked
  2026-10-16). It does not count toward our budget (index.html 0.5 KB br / 4 KB; core JS 89.3 / 90 KB — tight, +0.2 KB from the
  data-ui listener). If first paint outside the Pi Browser matters, consider `async`/lazy loading later (Pi docs prescribe the plain tag).
- **App Studio framing**: the SDK also recognises `https://appstudio-u7cm9zhmha0ruwv8.piappengine.com` as a host. If App Studio
  frames the app from that origin, set `CSP_FRAME_ANCESTORS_EXTRA=https://appstudio-u7cm9zhmha0ruwv8.piappengine.com`
  (not added by default: the brief fixed frame-ancestors to `'self' https://*.pinet.com https://*.minepi.com`).
- **connect-src**: the SDK's own API calls go to a backend URL handed over by the Pi host app; we allow
  `https://api.minepi.com` and `https://socialchain.app`. If the browser console shows a CSP block for another Pi host
  (e.g. a testnet API host), add it explicitly in `buildCsp`.
- `SameSite=None; Secure` applies only when `NODE_ENV=production` (`config.secureCookies`) — Railway sets it via the Dockerfile.
- Pi sign-in is now **on by default** in every environment (no key needed). Set `PI_AUTH_ENABLED=0` to keep it hidden.
- Integrity / minors Pi-KYC routes still use `GET /v2/me` (they need KYC fields App Studio does not return) — unchanged.
- No Railway change, no deploy done.
