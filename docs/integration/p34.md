# Phase 34 (الشفافية والامتثال) — integration steps

Branch `t7-p34`, migration **017** (`server/migrations/017_compliance.js`, additive only: 7 new tables + 2 indexes on `reports`).
No shared file was edited on this branch. Every step below is an exact edit for the integrator. Steps 1–4 are required.
Steps 5–9 are optional improvements; the feature works without them.

New files: `server/services/compliance.js`, `server/lib/compliance-lib.js`, `server/lib/compliance-policies.js`,
`server/migrations/017_compliance.js`, `compliance-ui.js`, `docs/COMPLIANCE.md`, `server/test/compliance.test.js`,
`tests/unit/compliance-lib.test.js`, `tests/e2e/compliance.e2e.test.js`.

## 1. `server/server.js`: register the service (REQUIRED)
Register it **after** `safety`, because it subscribes to safety's events and wraps `ctx.track`, which `growth` sets. Put it right below this line:
```js
  ctx.services.safety = require("./services/safety")(ctx);
```
and add:
```js
  ctx.services.compliance = require("./services/compliance")(ctx); // Phase 34: transparency, DSR, retention, PDPL support
```
The service registers its own scheduled jobs (`compliance.reportSync`, `compliance.deletions`, `compliance.transparency`, `compliance.retention`)
on `ctx.scheduler`, and `close()` already stops them through `ctx.scheduler.stop()`.

## 2. `server/server.js`: public readable pages (REQUIRED for /legal/* and /transparency)
In `handle()`, extend the GET SSR chain:
```js
      if (req.method === "GET" && (await ctx.services.creation.ssr(req, res, url) || await ctx.services.cspace.ssr(req, res, url) || await ctx.services.eventsPlus.ics(req, res, url))) return;
```
→
```js
      if (req.method === "GET" && (await ctx.services.creation.ssr(req, res, url) || await ctx.services.cspace.ssr(req, res, url) || await ctx.services.eventsPlus.ics(req, res, url) || await ctx.services.compliance.ssr(req, res, url))) return;
```
It only answers `/legal/:slug`, `/transparency` and `/transparency/:period`. Every other path returns `false`.

## 3. `index.html`: the lazy UI chunk (REQUIRED)
Add it after the notify chunk line (`<script src="notify-ui.js" data-chunk="notify"></script>`):
```html
<script src="compliance-ui.js" data-chunk="compliance"></script>
```
`tools/build.mjs` picks up `data-chunk` automatically, so the build needs no change. The chunk is about 10 KB brotli and is not in the main bundle budget.

## 4. `chunks.js`: route → chunk, plus idle warm-up (REQUIRED)
In `ROUTES` add:
```js
    compliance: ["mydata", "my-reports", "account-log", "policies", "transparency", "compliance", "decisions"],
```
Then extend the idle warm-up chain so the Settings entry card («بياناتي وخصوصيتي») and the admin entry show without visiting a route first:
```js
... .then(() => load("notify")).catch(() => { }).then(() => load("compliance")).catch(() => { }));
```
Note on `decisions`: when online, the chunk maps the old `#/decisions` route to the new account decision log. Offline, it falls back to `V12.decisions`.

## 5. `server/lib/notify-lib.js`: wording for the new notification kinds (recommended)
The service sends three new kinds: `report_update` (ref = report id), `privacy_request` (ref = request id) and `security_breach` (ref = breach id).
Without this step they render as the generic fallback «لديك إشعار جديد». In `KINDS`, add:
```js
  report_update: { tab: "system", imp: 55, ch: { inapp: 1, push: 1, email: 0 }, v: ["تحديث على بلاغك: اتُّخذ قرار"], label: "متابعة بلاغاتي", system: 1 },
  privacy_request: { tab: "system", imp: 60, ch: { inapp: 1, push: 1, email: 1 }, v: ["تحديث على طلبك بخصوص بياناتك"], label: "طلبات البيانات", system: 1 },
  security_breach: { tab: "system", imp: 95, ch: { inapp: 1, push: 1, email: 1 }, lock: ["inapp", "email"], v: ["تنبيه أمني مهم بخصوص بياناتك"], label: "تنبيهات حوادث البيانات", system: 1 },
```
In `hrefFor(n)`, before the final `return "/#/notifications";`, add:
```js
  if (n.kind === "report_update") return "/#/my-reports";
  if (n.kind === "privacy_request") return "/#/mydata";
  if (n.kind === "security_breach") return "/#/policies/privacy";
  if (n.kind === "removed") return "/#/account-log";
```
(The last line is optional: it sends «أُزيل محتوى لك» to the decision log, where the reason and the appeal button are, instead of the removed post.)
Run `tests/unit/notify-lib.test.js` after this edit.

## 6. `server/services/safety.js`: instant «no violation» updates (optional)
Reporters already get dismissals within 2 minutes through the scheduled sync. For instant delivery, in `resolveReport`, in the `else` (dismiss) branch, after `ctx.audit("REPORT_DISMISSED", …)` add:
```js
      bus.emit("REPORT_RESOLVED", { target: r.target, status: "dismissed" });
```

## 7. Consent hooks for personalization and post views (optional, honest gap)
`ctx.track` (analytics events) already honours the analytics consent through the wrapper in compliance.js. Two direct inserts do not go through it yet:
- `server/services/ranking.js` (the line inserting into `engagement_signals`): skip it when `!(await ctx.services.compliance?.hasConsent(uid, "personalization") ?? true)`.
- `server/services/content.js` (the line inserting into `post_views`): use `user_id = null` when `!(await ctx.services.compliance?.hasConsent(user.id, "analytics") ?? true)`.

## 8. `security-ui.js`: point the old export card at the new center (optional)
The old `GET /api/me/export` (ops.js, JSON only) still works and is untouched. In the security center, it is better to replace
`<a class="btn ghost" href="/api/me/export" download>تنزيل</a>` with `<a class="btn ghost" href="#/mydata">بياناتي</a>`.
