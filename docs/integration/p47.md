## API
- **v1 (public, bearer `mpk_` API key or `mpa_` OAuth token; anonymous allowed for reads at `DEVAPI_ANON_RATE_PER_MIN`=20/IP)**:
  `GET /api/v1/posts[?tag&limit&before]`, `/posts/:id`, `/posts/:id/comments`, `/users/:handle`, `/users/:handle/posts`, `/communities`, `/communities/:id`,
  `/communities/:id/posts`, `GET /api/v1/me` (scope `profile`), `POST /api/v1/posts` + `POST /api/v1/posts/:id/comments` (scope `write:posts`, or a bot token).
  **Every read runs as an anonymous viewer** (`content.filterVisible(rows, null)` + `visibility='public'` + not paid + community `type='public'`), whatever
  the token: no messages/E2EE routes exist, no followers-only/private/paid posts, no private-account profiles, no private/invite communities.
  API posts are always `visibility:'public'`; community must be public. CORS `*` (bearer only, no cookies), preflight handled.
- `GET /api/v1/openapi.json` — OpenAPI 3.0.3 **generated from the same `api({...})` definitions** that register the routes (+ `x-webhook-events`).
- **OAuth 2.0**: `GET /oauth/authorize?client_id&redirect_uri&scope&state&code_challenge&code_challenge_method=S256` → consent `#/oauth`;
  `GET|POST /api/oauth/authorize` (session + CSRF) → `{redirect}`; `POST /api/oauth/token` (form or JSON; `authorization_code` + PKCE S256 mandatory,
  exact redirect match, single-use 10-min code — reuse revokes what it issued; `refresh_token` with rotation + reuse detection → whole family revoked;
  `client_credentials` → bot token, secret required); `POST /api/oauth/revoke`. Access 1 h (`DEVAPI_ACCESS_TTL_S`), refresh 30 d.
  Scopes: `read`, `profile`, `write:posts` (user); `bot` only via client_credentials.
- **Portal (session)**: `/api/dev/meta|apps|apps/:id` (create/patch/delete=revoke all), `/apps/:id/secret` (rotate), `/apps/:id/keys`, `/keys/:id/rotate`,
  `DELETE /keys/:id`, `/apps/:id/webhooks`, `DELETE /webhooks/:id`, `/webhooks/:id/test`, `/apps/:id/deliveries`, `/deliveries/:id/retry`,
  `/apps/:id/bot`, `/apps/:id/installs` (+DELETE), `/communities/:id/bots`, `/connections` (+DELETE = user revokes an app).
  Admin: `POST /api/admin/devapi/apps/:id {status: active|suspended, rateLimit}`, `GET /api/admin/devapi/stats`, `GET /api/dev/apps?all=1`.
- Credentials: client secret `mps_`, API key `mpk_`, codes `mpo_`, tokens `mpa_`/`mpr_` — **sha256 at rest, shown once** (UI keeps the reveal across re-renders until «نسختُه»).
- **Rate limits**: sliding minute per API key / per OAuth token family; key limit ≤ app limit (admin-set) ≤ `DEVAPI_MAX_RATE_PER_MIN`; default `DEVAPI_RATE_PER_MIN`=60.
  Headers `X-RateLimit-Limit|Remaining|Reset`, 429 + `Retry-After`. In-memory per instance (Phase 48 distributes it).
- **Webhooks**: events `post.created`, `comment.created` (public content only), `bot.command`, `bot.mention`, `app.authorized`, `app.revoked`, plus `ping` test.
  `X-Mujtama-Signature: t=<unix>,v1=hex(HMAC_SHA256(secret, t + "." + body))`, `X-Mujtama-Event`, `X-Mujtama-Delivery`. Retries backoff 30 s·4ⁿ⁻¹,
  max 6 attempts (`DEVAPI_WEBHOOK_*`), leased job `devapi.webhooks` every 15 s; delivery log + manual retry. Production: https + non-private hosts only
  (dev/test allow http/localhost; `DEVAPI_ALLOW_PRIVATE_URLS=1` forces it).
- **Bots**: one bot account per app (`users.role='bot'`, no password, handle ends in `bot`), installed by a community owner/admin into **public communities only**;
  `/name args` matching the app's commands → `bot.command`, `@handle` → `bot.mention`; type re-checked at event time. Bot posts/comments only where installed.

## Gaps / for the integrator
- Webhook signing secrets are stored in plain text (HMAC needs them); no KMS/env encryption key (none allowed this phase).
- SSRF guard checks the hostname/IP literal, not DNS resolution (DNS-rebinding gap); redirects are not followed.
- Rate limits and the event de-dupe are per instance (in-memory).
- Bots cannot be installed into private communities by design; minors/age gating is not applied to OAuth consent.
- `POST_PUBLISHED`-based `post.created` (scheduled and approved posts included); edits/deletes are not webhook events yet.
- App directory/review flow not built (any signed-in user can create up to 20 apps; admins can suspend).
