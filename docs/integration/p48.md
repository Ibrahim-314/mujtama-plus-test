# Phase 48 — horizontal scaling «التوسع الأفقي» (integration notes)

Base 9eded6f (v2.15.0). Target 2.21.0 (no bump here). **No migration.** No new dependencies. Production unchanged unless
`REDIS_URL` / `NATS_URL` / `ROLE` / `CDN_CACHE` are set (none are on Railway). Full design + env table: `docs/SCALING.md`.

New files: `server/lib/scale.js` (adapters, roles, wiring), `server/lib/redis-lite.js` (RESP2 client), `server/lib/nats-lite.js`
(NATS text-protocol client), `server/lib/shard.js` (shard-key helper), `server/test/scale.test.js` (fake Redis/NATS servers in-test),
`deploy/k8s/*` (kustomize: web + 3 worker roles, HPAs, PDB, ingress; files only), `docs/SCALING.md`.

Shared-file lines:
- `server/server.js`: core import → `Scale`; `bus/cache/rl` now from `await Scale.createScale({ log, overrides })` (in-process classes by
  default); `ctx.scale`; `Scale.applyRole(ctx); Scale.applySessions(ctx)` right after the scheduler (before services);
  `await Scale.wireScale(ctx)` just before `minors` (realtime fan-out + `GET /api/admin/scale`); seed skipped on worker roles; worker
  roles: HTTP health-only gate (404 `worker_role`), no WS upgrade, no in-process interval jobs; `close()` closes adapters.
  createApp overrides `role`, `redisUrl`, `natsUrl` (tests).
- `server/repos/sessions.js`: object wrapped by `db.sessionCache` when set (only with `REDIS_SESSION_CACHE_MS>0`).
- `server/lib/http.js` `serveStatic`: +1 line `cdnHeaders(...)` (adds `CDN-Cache-Control` only when `CDN_CACHE=1`).
Merge note: other phases adding services should keep registering them before the `wireScale` line (any order works; it only wraps
`ctx.realtime` methods and adds one route). New queue kinds / scheduled jobs default to the `web` role unless listed in
`QUEUE_KINDS` / `SCHED_JOBS` in `scale.js`.

API: `GET /api/admin/scale` (admin) → `{role, node, adapters:{bus, cache, rateLimit, realtime, sessions}, redis:{ready}|null, nats:{ready}|null, stats}`.

Gaps: NATS TLS unsupported by the minimal client (in-cluster plaintext/token auth); Kafka not implemented (NATS chosen);
distributed `rl.hit` may overshoot by ≤1 RTT per node (`hitAsync` exact); presence/`realtime.online()` is per node; no live Redis/NATS
server was available, so adapters are verified against protocol fakes; KEDA queue-depth scaling not included; sharding is helper + doc only.
