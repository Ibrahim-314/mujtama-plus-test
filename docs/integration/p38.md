## What the UI team must know
- **Composer**: send `paid:{mode:"ppv", price}` or `paid:{mode:"supporters", minTierId?}` (+ optional `teaser`) with the normal post body,
  or `visibility:"supporters"`. Show the option only when `GET /api/me/creator` → `enabled` (tiers from the same call; `supporters` needs ≥ 1 tier).
  Errors: 400 `paid_invalid` | `price_invalid` (range 0.01–100) | `tier_invalid` | `paid_type` (post/article/video/audio only) |
  `paid_community` | `paid_media_owner`; 403 `minor_restricted`; 409 `creator_disabled` | `no_tiers` | `paid_media_used` | `conflict` (duplicate body);
  422 `spam`. Editing: `PATCH /api/posts/:id {text?, paid?:{…}|null}`; 400 `paid_on_create_only` when trying to make a free post paid.
- **Rendering**: any post with `locked:true` → show `text` (the teaser), blurred placeholders from `lock.media` (no URLs are sent), and a lock card:
  `lock.mode==="ppv"` → «افتح بـ {lock.price} Pi» (enabled when `lock.purchasable`); `"supporters"` → the `lock.tiers` (each with amount/perks)
  linking to the P37 support flow, `lock.minTier` for the label. `lock.reason`: `sign_in` → prompt login, `minor_restricted` → no CTA,
  `not_configured` → Pi off text. `paid` (mode/price) is present on every paid post, also unlocked ones (badge «مدفوع» / «للداعمين»).
- **PPV flow**: `POST /api/paid/:postId/intent` → `{intent, purchaseId}` → pass `intent` unchanged to `Pi.createPayment` → usual
  `/api/pi/payments/approve|complete|cancel`. After `complete` (`receipt.status:"completed"`) re-fetch `GET /api/posts/:id` (or
  `GET /api/paid/:postId` → `unlocked`). Errors: 400 `not_paid` | `own_post` | `not_ppv`; 403 `minor_restricted` | `blocked`;
  404; 409 `already_unlocked` (just re-fetch) | `creator_disabled` | `pi_not_linked` (prompt Pi link); 429; 501 `not_configured`.
- **Media** of a locked post is never in the payload; for an unlocked post the usual `/media/…` URLs work with the session cookie
  (same origin) — they answer 403 `paid_locked` otherwise. Do not put paid media URLs in the service worker cache (they are `no-store`).
- **My purchases** `/#/purchases`: `GET /api/me/purchases` (`refundEligible` → show «طلب استرداد» until `refundUntil`; `refundRequest.status`).
  Request: `POST /api/paid/purchases/:id/refund-request {reason?}`; 409 codes `refund_pending`, `not_refundable`, `refund_not_eligible`,
  `refund_window_passed` (messages are user-ready Arabic).
- **Creator dashboard**: `GET /api/me/paid-posts` (unlocks, revenue, net, refunds per paid post); earnings gain `bySource.ppv`.
- **Admin**: refund queue `GET /api/admin/paid/refunds?status=pending` + `POST /api/admin/paid/refunds/:id/approve {note?, txid?}` |
  `/reject {note?}`; duplicate purchases arrive automatically with `kind:"duplicate"`. Bodies contain a `status` field (request status).
- **Notifications**: route `/#/purchases` (buyer kinds `ppv_refunded`, `paid_refund_rejected`, `paid_refundable`); `ppv_purchased` opens the post.
- CSP: no inline handlers (`data-ui` / addEventListener), as since 36b.
