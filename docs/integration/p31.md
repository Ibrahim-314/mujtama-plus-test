## 2. Recommended (optional) edits

### server/services/content.js — zero-window gate (content never appears, not even for a fraction of a second; no POST_PUBLISHED / mention fan-out while held)
In `createPost`, right after the duplicate-id check (`if (await db.get("SELECT 1 x FROM posts WHERE id=$1", [pid])) throw ...`):
```js
    if (ctx.services.automod) status = await ctx.services.automod.gate(user, { kind: "post", id: pid, text: full, doc: data.doc, status });
```
In `comment`, replace the INSERT block:
```js
    const cid = acceptId(b.id, "c");
    const cstatus = ctx.services.automod ? await ctx.services.automod.gate(user, { kind: "comment", id: cid, text, status: "published" }) : "published";
    await db.run("INSERT INTO comments(id,post,author,parent,text,created_at,anchor,status) VALUES($1,$2,$3,$4,$5,$6,$7,$8) ON CONFLICT DO NOTHING", [cid, p.id, user.id, parent?.id || null, text, now(), anchor, cstatus]);
```
and return `status: cstatus` instead of `status: "published"`. Keep emitting `COMMENT_CREATED` (the automod bus handler records the item from it).
Without this hook everything still works through the bus (POST_CREATED → quarantine within milliseconds); the only
difference is a tiny visibility window and that mention/publish notifications may already have gone out.

### server/lib/llm.js — optional model classifier used for borderline items when `AUTOMOD_LLM=1`
The service calls `ctx.llm.classify({ text, labels, lang })` only if that function exists and expects `{ score: 0..1, categories?, provider? }`.
Suggested addition inside `createLLM` (reuses the OpenAI-compatible key, the daily budget and `llm_usage`):
```js
  async function classify({ text, labels = ["abuse", "threat", "hate", "fraud"] }) {
    const p = providers.openai; if (!p || active === "extractive") return null;
    const est = (text.length / 3.5 / 1000) * limits.priceIn + (60 / 1000) * limits.priceOut;
    if ((await spentToday()) + est > limits.dailyBudget) return null;
    const r = await fetch((env.OPENAI_BASE_URL || "https://api.openai.com/v1").replace(/\/$/, "") + "/chat/completions", { method: "POST",
      headers: { "Content-Type": "application/json", Authorization: "Bearer " + key },
      body: JSON.stringify({ model: p.model, temperature: 0, max_tokens: 60, response_format: { type: "json_object" },
        messages: [{ role: "system", content: `صنّف النص العربي. أعد JSON فقط: {"categories":{${labels.map(l => `"${l}":0..1`).join(",")}}}` }, { role: "user", content: text.slice(0, 4000) }] }) });
    if (!r.ok) return null; const j = await r.json();
    await record("openai", j.usage?.prompt_tokens || 0, j.usage?.completion_tokens || 0, ((j.usage?.prompt_tokens || 0) / 1000) * limits.priceIn + ((j.usage?.completion_tokens || 0) / 1000) * limits.priceOut);
    const c = JSON.parse(j.choices?.[0]?.message?.content || "{}").categories || {};
    return { categories: c, score: Math.max(0, ...Object.values(c).map(Number).filter(n => !isNaN(n))), provider: "openai" };
  }
```
(expose it in the returned object as `classify`). Zero-budget default: no key → the function returns null / is absent and the local classifier decides alone.

## 3. Environment variables (all optional, safe defaults, nothing paid)
| Var | Default | Meaning |
|---|---|---|
| `AUTOMOD_ENABLED` | `1` | `0` disables scanning |
| `AUTOMOD_DELAY_MIN` | `10` | smart-delay length (minutes) |
| `AUTOMOD_ADAPTIVE_RL` | `1` | `0` disables adaptive rate limits (also `createApp({ adaptiveRateLimits: false })`) |
| `AUTOMOD_LLM` | off | `1` = use `ctx.llm.classify` for borderline items (needs the llm.js addition + `OPENAI_API_KEY`) |
| `AUTOMOD_IMAGE_URL` | off | external/self-hosted image classifier endpoint (raw bytes in, JSON score out) |
| `AUTOMOD_IMAGE_TOKEN` | — | bearer token for the above |

Tests can pass `automodEnv: {...}` to `createApp` overrides instead of process env.

## 4. Things to watch when running the full suite after integration
- **Adaptive limits**: brand-new accounts post 6/min instead of 8 (comments 11/min, follows 15/min, messages 15/min, invites 5/min).
  Existing suites register fresh users; if any of them now hits 429, pass `adaptiveRateLimits: false` in `server/test/helpers.js`
  `createApp({...})` overrides (one word) rather than changing the feature.
- **Quarantine in other suites**: posts/comments with insults now become `status='held'` a few ms after creation.
  Known overlap: `communities.test.js` posts the comment «انت غبي وحمار» and only reads the cmod report → removes it; this is expected to keep working (not re-run here, per the brief)
  (the report still exists; removal sets `removed`). Tests asserting `published` on abusive text would need the author to be admin or the text changed.
- The first registered account is admin (bootstrap) and admins are exempt from automod.
