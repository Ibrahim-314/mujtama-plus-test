## Conventions
JSON, session cookie, `X-Requested-With: mujtama` on writes. Errors: `{error (Arabic, user-ready), code, requestId}`.
Amounts are Pi numbers (≤ 7 decimals), `currency:"PI"`. Timestamps ISO-8601. Statuses: `draft|in_review|rejected|awaiting_funds|active|paused|completed|removed`.

### Shapes
- **Campaign**
  ```
  {id:"ac_…", name, objective:"reach"|"engagement"|"visits", status, postId,
   post:{id, type, title|null, text (≤280 chars), topic|null, lang|null, status, visibility, createdAt}|null,
   targeting:{topics:[slug], languages:["ar"…], countries:["SA"…]},
   budget:{total, dailyCap, bidCpm, spent, remaining, funded:boolean, fundedAmount, currency:"PI"},
   freqCap:{impressions, perHours}, startAt, endAt, reviewNote|null,
   review:{decision:"approve"|"reject", reasons:[code], note|null, at, automated:boolean}|null,
   piEnabled, fundNote? (only when Pi is off: «مدفوعات Pi غير مفعّلة بعد»), actions:[…], label:"مُروَّج",
   submittedAt|null, completedAt|null, createdAt, updatedAt,
   stats? (detail/create/update/action responses), intent? (detail, owner, while an unpaid intent is open)}
  ```
  `actions` drives the buttons: `edit` + `submit` (draft, rejected) · `edit_limited` (awaiting_funds, active, paused: name, dailyCap,
  endAt, freqCap only) · `pause` (active) · `resume` (paused) · `fund` (not funded and draft|in_review|awaiting_funds) · `delete` (not removed).
- **Stats** `{days:[StatRow], totals: StatRow (day:null), hides:[{reason, count|null, countText}], kAnon:10}`
  **StatRow** `{day:"YYYY-MM-DD"|null, impressions:number|null, impressionsText, clicks:number|null, clicksText, spend, ctr:number|null}` —
  `null` + `…Text:"أقل من 10"` whenever a count is below 10 (k-anonymity); `ctr` is a percentage with 2 decimals, `null` if either count is hidden.
  `spend` is always exact (it is the advertiser's own money). Show `…Text` in the UI; use the numbers only for the chart (treat null as a hatched/empty bar).
- **List item** = Campaign (without `stats`/`intent`) + `totals: StatRow`.
- **Promoted feed item** = a normal post object (`content.toClient`) + `promoted:{campaignId, label:"مُروَّج", advertiser:{id, handle, name, avatar}, objective, token}`.
  The advertiser is also in the feed response's `users[]`. Promoted items carry no `why`/`fresh`.
- **Audience** `{bucket:"lt10"|"10-100"|"100-1000"|"1000-10000"|"10000-100000"|"100000+", min, max|null, label}` (label is Arabic-ready, e.g. «أقل من 10», «100–1,000»).

## What the UI team must know
- **Feed card**: render `promoted` posts with the «مُروَّج» label (`promoted.label`) and `promoted.advertiser`; ⋯ menu → `GET /api/ads/why/:campaignId`
  sheet (reasons + `controls`), «إخفاء الإعلان» / «إخفاء هذا المعلن» → `POST /api/ads/hide` and remove the card locally.
  Impression: once per card when ≥ 50 % visible for ≥ 1 s → `POST /api/ads/events {campaignId, type:"impression", token}`;
  click on the card/post → same with `type:"click"`. Never retry a `counted:false`. A token is valid 24 h; reload the feed for new ones.
- Ads are positioned by the server (after organic #8, #16, … counted from the cursor); do not reorder them. `nextCursor` stays organic.
- **Fund flow**: `POST …/fund` → pass `intent` unchanged to `MPPi.pay` (purpose `ads` is inside) → usual `/api/pi/payments/approve|complete|cancel`
  → re-fetch the campaign (`budget.funded:true`; status `active` if it was `awaiting_funds`). Pi off: hide/disable «تمويل» and show `fundNote`.
- **Wizard**: topics from `/api/ads/topics`; call `/api/ads/estimate` on every targeting change (debounced) and show `audience.label`.
  A 400 `targeting_sensitive` should show the Arabic `error` under the topic field.
- **Dashboard**: `stats.days` for the inline SVG chart, `stats.totals` for tiles, `…Text` everywhere a count is displayed; `review`/`reviewNote`
  for rejections; `actions` for buttons.
- **Notifications**: `ad_approved`, `ad_rejected`, `ad_budget_low`, `ad_completed` → `/#/ads/campaigns/:id`.
- Minors: every advertiser endpoint answers 403 `minor_restricted`; hide the «إعلاناتي» entry for them (`/api/age` → minor).

## Deviations / additions vs the contract (all additive)
1. Extra tables `ad_tokens` (single-use markers for feed tokens, hashed, purged after 7 days) and `ad_meta` (token key + daily salts).
   `ad_campaigns.freq_cap` is stored as two columns `freq_impressions` / `freq_hours`; extra money/lifecycle columns (`funded_amount`, `spent`,
   `charged`, `intent_id`, `low_notified`, `automod`, `submitted_at`, `completed_at`). `ad_prefs` has an extra `hidden_ads` column ("hide this ad").
2. Extra error codes: 400 `review_invalid`, `event_invalid`, `token_invalid`; 403 `forbidden`; 409 `pi_not_linked` (from the Pi service).
3. Extra routes: `GET /api/ads/config`. `/api/ads/why` and `/api/ads/events` also work signed out.
4. Pure CPM: clicks are counted but never charged (the contract mentions "impressions/clicks are charged" in the ledger sentence).
5. With personalised ads off, language targeting still applies (UI language is treated as contextual); topic- and country-targeted
   campaigns are not shown.
6. Frequency windows reset at the UTC day change (salt rotation), so `perHours` is capped at 24.
7. Unspent budget is not auto-refunded (no A2U payments from the server); it stays in `ads:budget:<cid>` until the operator refunds via Pi,
   which removes the campaign and journals the unspent part back (`PI_PAYMENT_REFUNDED`).
8. Signed-out ads: implemented in the service (`pick(null)` → untargeted campaigns only), but `/api/feed` requires sign-in, so no
   signed-out surface shows ads yet.
9. Moderators: the review queue accepts `users.role` `admin` or `moderator` (site-level; community moderators are not reviewers).
