## Push (Android + iOS 16.4+ installed PWA)
Keys from env only: `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` (+ `VAPID_SUBJECT`). In **production** (or `VAPID_ENV_ONLY=1`) the server never generates
keys: no env key and no previously stored pair → `GET /api/push/vapid` 503 `push_not_configured` «إشعارات الدفع غير مفعّلة على الخادم بعد (مفاتيح VAPID غير مضبوطة)».
A pair already stored in `notify_keys` keeps working (existing subscriptions are not broken). Dev/test keep generate-once (`VAPID_ENV_ONLY=0`).
`GET /api/pwa/config` (public) → `{push:{enabled, source: env|stored|dev|none, note?}, shareTarget, release, minIos:"16.4"}` — never returns keys.
iOS outside the installed app: #/app and the existing notify-core "needs-install" path tell the user to install first.

## Service worker (sw.js)
- Store-less updates: an **update** no longer auto-`skipWaiting`; pwa-ui shows «تحديث جديد لمجتمع بلس متوفر» → `mp-skip-waiting` → reload once.
  First install still activates immediately. `reg.update()` on focus (≥30 min) and hourly; #/app «تحقق من التحديثات».
- Offline reading: network-first `READ` endpoints (bootstrap, collections/sync, feed, explore, stories, digest, posts/:id[/paragraphs|summary|comments],
  topics/:t/page, series/:id, u|users/:h) in cross-version cache `mp-api` (300 entries), deleted on `POST /api/auth/logout`.
- Offline drafts: `PUT|DELETE /api/drafts/:id` failing on network → IndexedDB `mp-pwa/drafts` (coalesced per id) → 202 `{queued:true}` (PUT echoes `base`);
  `GET /api/drafts` merges the queue; replay via Background Sync `mp-drafts` or page `mp-drafts-flush` (on `online`). 409 conflict → dropped, server copy wins, toast.
- Share target: `POST /share-target` (manifest, multipart: title/text/url + ≤4 images ≤15 MB) → cache `mp-share` → 303 `/?source=share#/home`
  → composer prefilled; images uploaded via `/api/media` when online.
- `mp-version` message (MessageChannel) → VERSION.

favicon 32, 15 splash. `capacitor.config.json` (appId `plus.mujtama.app`, webDir `dist`); `CAP_SERVER_URL=https://…` → shell loads the live site
(UI updates without store). `npm run cap:*` writes config and runs `npx cap` only if `@capacitor/cli` is installed (not added); header of
`tools/capacitor.mjs` has the one-time native setup. No native build run, no store accounts.

## Gaps
- `beforeinstallprompt` firing before the lazy chunk loads is not caught (Chrome's own install UI/menu still works) — catching it would cost core bytes.
- Share target needs the SW (installed PWAs always have it); no server-side POST /share-target fallback.
- Update prompt and iOS push not exercised in e2e (needs a second build / a real iPhone). Store-app push needs @capacitor/push-notifications + FCM/APNs.
- Production without VAPID env and without a stored pair now has push disabled (by design) — set the env keys on Railway to enable.
