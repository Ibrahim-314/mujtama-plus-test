## What the UI team must know
- Pi config first (`GET /api/pi/config`); hide send/support buttons when `enabled:false` (intents answer 501).
- **Tip flow**: `POST /api/tips/intent {toHandle, amount, postId?, message?, anonymous?, showAmount?}` → pass `intent` (`{amount, memo, metadata}`
  exactly as returned) to `Pi.createPayment`, then the usual phase-36 callbacks (`/api/pi/payments/approve|complete|cancel`).
  The tip is credited when the server sees the completed payment; `complete` returning `receipt.status:"completed"` is the moment to show
  success. A tip may silently go to review (`held`) — show the same success to the sender.
- **Support flow**: `POST /api/support/intent {toHandle, tierId, anonymous?, showAmount?}` → same Pi flow. Each month is a new payment;
  show a "renew" button when `myStatus.state` is `due` (or `lapsed`/`cancelled` to restart). 409 `support_active` = not yet renewable.
  Cancel: `POST /api/support/:supportId/cancel` (perks continue until `activeUntil`; show the returned `note`).
- Errors to map: 400 `tip_max`, `self_tip`; 403 `minor_restricted`, `blocked`; 404 creator/tier/post; 409 `creator_disabled`,
  `support_active`, `pi_not_linked` (prompt to link Pi); 429 `tip_daily_limit`, `tip_hourly_limit` (message is user-ready Arabic);
  501 Pi off. Amounts: > 0, up to 7 decimals.
- **Response bodies carry fields named `status`** (release/reject → tip status) — don't spread them over the HTTP status.
- Creator settings screen: `GET/PUT /api/me/creator` (`enabled`, `showAmounts`, `tiers` ≤ 3 with `{id?, name, amount, perks}`; send the full
  list — tiers left out are retired; `limits.maxTierAmount` for the input max; `feeBps` to show the platform fee). Minors get 403 on enable.
- Public creator page: `GET /api/creators/:handle/support` (tiers, stats, `myStatus`, recent `wall`); honour roll
  `GET /api/creators/:handle/wall?period=month|all`. `user:null` = anonymous («داعم مجهول»), `amount:null` = hidden.
- Post badge: `GET /api/posts/:id/tips` → `{count, total|null, recent}`.
- Earnings dashboard: `GET /api/me/earnings?period=day|week|month` or `from/to` (YYYY-MM-DD, UTC, ≤ 1 year); download `csvUrl` with the
  session cookie (plain GET, it is a file). My ledger: `GET /api/me/ledger?cursor=`. My supports: `GET /api/me/supporting`.
- Notification routes to add: `/#/earnings` (creator), `/#/u/<handle>/support` and `/#/supporting` (supporter) — or remap in `hrefFor`.
- Admin screens: held queue `GET /api/admin/tips/held` + `POST /api/admin/tips/:id/release|reject {note?, txid?}`; ledger health
  `GET /api/admin/ledger/check` (`balanced`, `imbalances`). Refunds of completed tips/support use the existing Pi refund action
  (`POST /api/admin/pi/payments/:intentId/refund`); the ledger reverses automatically.
