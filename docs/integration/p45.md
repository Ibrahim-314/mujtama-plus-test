## Privacy model
Usage time is measured on the device only (`localStorage["mp.wb.u"]`: seconds + sessions per local day, 35 days). Active = tab visible
and an interaction in the last 60 s; a 5-min gap starts a new session. The server stores only the user's choices and — after an explicit
opt-in (`shareTotals`) — one aggregated row per ISO week (seconds, sessions, active days). Turning the opt-in off deletes every stored week;
weeks older than 8 are pruned by the job.

## API (`server/services/wellbeing.js`)
- `GET /api/wellbeing/config` → `{ free, breaks, maxDailyLimit, email (SMTP configured), localOnly, week }`
- `GET|PUT /api/wellbeing/settings` → `{ breakMinutes (0|15|20|30|45|60|90), dailyLimitMinutes (0 or 10–600), hideCounts, focus, weeklyReport, shareTotals, emailReport }` (partial PUT; 400 `settings_invalid`)
- `POST /api/wellbeing/weekly` `{week,seconds,sessions,days}` or `{weeks:[…≤8]}` — 403 `not_opted_in`, 400 `totals_invalid` (future / >8 weeks old / impossible values)
- `GET|DELETE /api/wellbeing/weekly`
- Job `wellbeing.weekly` (hourly, `WELLBEING_JOBS=0` / `WELLBEING_JOB_INTERVAL_MS`): one in-app notification `wellbeing_weekly` per finished shared week;
  email via `mail.sendNotification` only when `ctx.mailer.enabled` AND `emailReport` AND verified address. Users who keep totals local get the report locally (toast + #/wellbeing).
