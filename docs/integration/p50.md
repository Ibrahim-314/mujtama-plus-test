## Invite mode (hooks wrap the existing auth routes; users.js is not edited)
- `POST /api/auth/register {invite, ref?}`: without a valid code → 403 `invite_required` `{reason: missing|unknown|used|expired|revoked, waitlist:true}`.
- `POST /api/auth/pi {invite?, ref?}`: a NEW Pi account without a code is created and then parked (`users.status='waitlist'`, sessions deleted,
  cookie cleared, waitlist row `@handle`) → 403 `invite_required {parked:true}`. Signing in again with a code activates it. Existing accounts are never affected.
- Client: `?invite=` / `?ref=` are kept in sessionStorage and added to both calls by the launch chunk (Remote.api wrapper).

## API (session, `X-Requested-With: mujtama`; staff = role admin|moderator)
- Launch: `GET /api/launch/config` → `{mode, inviteRequired, staff,…}` · `POST /api/launch/waitlist {contact(email|@handle)?, name?, ref?}` →
  `{already, state, position}` (anonymous OK; signed-in uses @handle) · `GET /api/launch/invites/:code` → `{valid, reason}` ·
  staff: `GET /api/launch/stats`, `GET /api/admin/launch/waitlist?status=`, `POST /api/admin/launch/waitlist/:id|next/invite {count?, days?}` → codes
  (sent manually, no e-mail), `GET|POST /api/admin/launch/invites {count, maxUses, days, note}`, `POST /api/admin/launch/invites/:code/revoke`.
- Help center: `GET /api/helpcenter/articles?q=&kind=faq|article&category=&all=1(staff)` (Arabic-normalised LIKE search; FAQ items include body) ·
  `GET /api/helpcenter/articles/:slug` · staff `POST /api/admin/helpcenter/articles`, `PUT|DELETE /api/admin/helpcenter/articles/:id`.
  12 Arabic items are seeded once (flag `launch_meta.help_seeded`) and never re-seeded. The old static `/api/help` (phase 33 safety resources) is untouched.
- Tickets: `POST /api/tickets {subject, body, category, attachments:[own media ids ≤4]}` · `GET /api/tickets` · `GET /api/tickets/:id`
  (owner or staff; others 404; internal notes hidden; staff shown as «فريق الدعم») · `POST /api/tickets/:id/messages {body, attachments?, internal?(staff)}`
  (staff reply → `answered` + notify `support_reply`, best effort; user reply reopens) · `POST /api/tickets/:id/status {status, priority?(staff)}`
  (user: open/resolved/closed only) · staff `GET /api/staff/tickets?status=&category=&assignee=me`, `POST /api/staff/tickets/:id/assign {assignee:"me"|uid}`.
  Max 10 open tickets per user.
- Ambassadors: `POST /api/ambassadors/apply {motivation≥20, region?, links[https ≤3]}` · `GET /api/ambassadors/me` → `{ambassador, stats, invites}` ·
  `POST /api/ambassadors/me/invites` (approved; 5 uses / 30 days each) · public `GET /api/ambassadors` (approved handles → 🎖 badge on profiles) ·
  staff `GET /api/admin/ambassadors?status=`, `POST /api/admin/ambassadors/:uid/review {decision: approve|reject|revoke, note (required unless approve)}`.
  Stats: referrals, last 30 days, active last 30 days (posted), invites used/issued. Referral via `ref` code on sign-up or an ambassador's invite code.
