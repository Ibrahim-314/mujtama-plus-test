## 1. Required edits

### server/server.js — register the service LAST (after `calls`, and after any other Track 7 service that wraps routes or `content`)
It wraps, at registration time, `ctx.services.content.filterVisible / canSee / toClient` and the handlers of
`POST /api/auth/register`, `PUT /api/privacy`, `PATCH /api/profile`, `POST /api/posts`, `GET /api/posts/:id`,
`GET /api/posts/:id/comments`, `GET /api/search`, `GET /api/search/full`, `GET /api/search/suggest`, `GET /api/bootstrap`.
Wrappers compose with other wrappers (each wraps whatever is current), so it only has to come after the services that own those routes.
```js
  ctx.services.calls = require("./services/calls")(ctx);
  ctx.services.minors = require("./services/minors")(ctx);       // Phase 35: age, minor defaults, labels, age filter, escalation, family links
  if (config.seedDemo) await require("./services/seed")(ctx, process.env.SEED_ROOT || config.webRoot);
```
(`ctx.services.minors.hooked` lists the routes it actually wrapped — useful as a startup sanity log.)
`server/worker.js` needs nothing (it calls `createApp`).

### index.html — two lazy chunks (keeps the 90 KB core budget untouched)
```html
<script src="notify-ui.js" data-chunk="notify"></script>
<script src="minors-core.js" data-chunk="minorscore"></script>
<script src="minors-ui.js" data-chunk="minors"></script>
```

### chunks.js — load them early (the cover must be in place for the first feed render and the register form), core first
Add inside `Chunks()` next to `callsChunks()`:
```js
  // phase 35: minors-core (rules) then minors-ui (cover, age gate field, #/age #/family #/urgent #/safety-cases)
  (function minorsChunks() {
    const R = ["age", "family", "urgent", "safety-cases"];
    const want = () => R.includes((location.hash.split("/")[1] || "").split("?")[0]);
    const go = () => load("minorscore").then(() => load("minors")).then(() => { if (want()) route(); }).catch(() => { });
    addEventListener("hashchange", () => { if (want() && (window.__CHUNKS || {}).minors && !loaded.minors) go(); });
    (window.requestIdleCallback ? (f) => requestIdleCallback(f, { timeout: 800 }) : (f) => setTimeout(f, 300))(go);
  })();
```
The UI module also re-renders once on load and injects the birth-date field into an already-open register form, so a late
load is safe. (Server-side filtering does not depend on the UI at all.)

## 3. Env vars (all optional, all off/no-cost by default)
`MINORS_MIN_AGE` (13), `MINORS_REQUIRE_DOB` (off), `MINORS_PI_KYC` (off; uses existing `PI_API_URL`), `MINORS_AUTHORITY_BODIES`
(`ncmec,national_hotline,police`), `MINORS_AUTHORITY_CHANNEL`, `MINORS_OPERATOR_CONTACT`, `MINORS_HELPLINES` (JSON), `SAFETY_ALERT_EMAIL`
(needs existing `SMTP_URL`). **No authority report is ever sent automatically**; the operator must configure the real channel and submit manually.

## 4. Operator checklist before enabling in production
1. Add at least one `lead` to the safety team: `PUT /api/safety/staff/:userId {role:"lead"}` (admins are leads implicitly).
2. Set `MINORS_AUTHORITY_CHANNEL` / `MINORS_OPERATOR_CONTACT` and verify `MINORS_HELPLINES` numbers for the jurisdiction.
3. Verify Pi's `/v2/me` actually exposes a KYC field before setting `MINORS_PI_KYC=1`.
4. Existing users start as `unknown` age: they keep seeing sensitive posts covered (as before) but new `adult/graphic/gambling`
   labels are hidden until they declare an age — expected, and announced in Settings («أكّد تاريخ ميلادك»).
