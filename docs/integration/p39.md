## Conventions
JSON, session cookie, `X-Requested-With: mujtama` on writes (as everywhere). Errors: `{error (Arabic, user-ready), code, requestId}`.
Prices/amounts are Pi numbers (≤ 7 decimals), `currency:"PI"`. Timestamps ISO-8601. Cursors are opaque strings (`next`, pass back as `cursor`).

### Shapes
- **Image** `{id, url, thumb, w, h, alt}` — `url`/`thumb` are `/media/…` paths; `w`/`h` are `null` (uploads carry no dimensions yet), `thumb` = `url` for now.
- **ListingCard** `{id, kind:"product"|"service", title, price, currency, category, condition:"new"|"used"|"na", delivery:"pickup"|"shipping"|"digital"|"onsite",
  location|null, status, quantity|null (null = unlimited), soldOut, cover: Image|null, imageCount, communityId|null, createdAt, updatedAt,
  seller:{id, handle, name, avatar, rating:{avg, count}}, mine?:true, views? (owner only)}`
- **Listing** = ListingCard + `{description, images:[Image] (ordered, first = cover), views, seller.sales, canBuy, buyReason?, piEnabled, buyNote?, maxQty}`.
  `buyReason`: `sign_in` | `own_listing` | `minor_restricted` | `blocked`* | `sold_out` | `unavailable`* (draft/paused, only visible to owner/admin) | `not_configured`
  (Pi off; `buyNote` = «مدفوعات Pi غير مفعّلة بعد» — show it under the disabled buy button). *extras beyond the contract list.
- **Order** `{id, listingId, title, listing:{id,title,kind,delivery,status,cover}|null, buyer:{id,handle,name,avatar}, seller:{…}, role:"buyer"|"seller"|"admin",
  qty, unitPrice, total, fee, currency, status, conversationId, createdAt, updatedAt, autoReleaseAt|null (when delivered),
  dispute:{id,status,reason,resolution}|null, review: Review|null, actions:[…], escrow:{state,amount,fee,buyerAmount,sellerAmount,heldAt,settledAt}|null,
  timeline:[{status, at, label}], tracking|null, paymentIntentId|null (buyer/admin), intent? (buyer, while pending_payment and the intent is still open)}`.
  Lists (`/api/me/market/orders`) return the same object **without** `escrow`, `timeline`, `tracking`, `paymentIntentId`, `intent`.
  `actions` drives the buttons: buyer `pay`,`cancel` (pending) · `confirm`,`dispute` (paid_held/shipped/delivered) · `review` (completed, none yet);
  seller `cancel` (pending, paid_held) · `ship`,`deliver`,`dispute` (paid_held) · `deliver`,`dispute` (shipped) · `dispute` (delivered). While a dispute is open: none.
- **Review** `{id, orderId, listingId, rating, text, reply|null, repliedAt|null, buyer:{id,handle,name,avatar}|null, createdAt}`
- **Dispute** `{id, orderId, order: Order(brief), openedBy, openerRole:"buyer"|"seller", reason, text, evidence:[Image], status:"open"|"seller_responded"|"resolved",
  resolution|null, buyerAmount|null, resolver (admin view only), note|null, createdAt, updatedAt, respondedAt, resolvedAt, messages:[{id, author, role:"buyer"|"seller"|"staff", text, evidence:[Image], createdAt}]}`
  (`seller_responded` = the other party answered; it is set whichever side opened.)

## What the UI team must know
- **Pay flow**: `POST …/order` → pass `intent` unchanged to `MPPi.pay` (purpose `market` is already inside the intent) → usual
  `/api/pi/payments/approve|complete|cancel`. After `complete`, re-fetch `GET /api/market/orders/:id` → `status:"paid_held"`, `escrow.state:"held"`
  (the server moves it on the Pi completion event; poll once or twice if the first read still says `pending_payment`).
  If the user abandons, `GET` the order: `intent` is offered again while it is open (`actions` contains `pay`); unpaid orders auto-cancel after 24 h.
  Pi off: `GET /api/market/config` → `piEnabled:false`, listing `canBuy:false, buyReason:"not_configured", buyNote`; the order call answers 409 `not_configured`.
- **Order conversation**: `order.conversationId` is a normal chat conversation (`kind:"group"`, title «🛒 <listing title>», exactly the two members,
  both accepted, no admins so nobody can add members or change its settings). Open it with the existing chat UI (`#/chat/<id>`).
  System messages: `kind:"system"`, `text` = Arabic sentence, `meta:{event:"market", step, order, …}` with `step` ∈ `pending_payment, paid_held, shipped
  (meta.tracking), delivered, completed (meta.auto), cancelled, refunded, disputed (meta.dispute), dispute_resolved (meta.resolution, meta.buyerAmount)}`.
  Render unknown system events by their `text`.
- **Timeline/escrow**: `timeline` is already sorted; `autoReleaseAt` shows «يُفرج عن المبلغ تلقائياً في …» when delivered.
- **Images**: upload with the existing `POST /api/media` (raw image), then send the returned `id` (or `{id, alt}` to set alt text; order = gallery order).
- **Notifications** (all `ref`-based, routes per contract): `market_order_new` / `market_order_paid` / `market_dispute_opened` → seller (or the other party);
  `market_order_shipped` / `market_order_delivered` → buyer; `market_order_completed` → seller (both on auto-release); `market_review` → seller
  (href `/#/market/seller/<handle>`); `market_dispute_resolved` → both.
- **Seller rating** on cards and the product page (`seller.rating.avg/count`, `seller.sales` on the full listing and seller page).
- CSP strict as since 36b: no inline handlers.

## Deviations / additions vs the contract (all additive)
1. Extra error codes: 400 `qty_invalid`, `review_invalid`, `dispute_invalid`, `evidence_invalid`, `resolution_invalid`, `split_invalid`;
   403 `blocked`; 409 `insufficient_quantity`, `invalid_state`, `review_exists`, `dispute_exists`, `dispute_resolved`;
   422 `listing_rejected` (automod hold/escalate verdict — the contract only names `spam`; listings have no "held" state, so they are refused instead).
2. Extra `buyReason` values `blocked` and `unavailable`.
3. Extra table `market_dispute_messages` (the contract lists dispute "messages" without a table); the listing condition column is `item_condition`.
4. Either party may open a dispute (`opened_by`); seller cancel after payment → `refunded` (not in the contract's state list for cancel).
5. Split resolution ends the order as `completed` with `escrow.state:"split"`; partial Pi refunds are manual for the operator (recorded in escrow/ledger only).
6. Extra read-only route `GET /api/market/config`; `GET /api/search` also returns `listings` for normal searches.
