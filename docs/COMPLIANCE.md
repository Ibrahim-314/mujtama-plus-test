# مجتمع بلس — الشفافية والامتثال (المرحلة 34، v2.8)

> **تنبيه مهم:** هذه المرحلة **دعم هندسي** لالتزامات نظام حماية البيانات الشخصية السعودي (PDPL) ولوائحه التنفيذية،
> **وليست استشارة قانونية** ولا شهادة امتثال. نصوص الشروط والخصوصية مسودة كتبها مهندسون بلغة واضحة، ويجب أن يراجعها
> مختص قانوني قبل الاعتماد عليها. المسائل التنظيمية (التسجيل في المنصة الوطنية لحوكمة البيانات، تعيين مسؤول حماية بيانات،
> تقييم أثر المعالجة، عقود المعالِجين، ضمانات النقل خارج المملكة) قرارات تشغيلية خارج نطاق الكود.

## مبدأ التصميم: خريطة بيانات واحدة
`DATA_MAP` في `compliance-lib.js` تصف كل جدول فيه بيانات شخصية: كيف تُحدَّد صفوف المستخدم، الغرض، الفئة، مدة الاحتفاظ،
وما يحدث عند الحذف (`delete` / `scrub` مسح المحتوى / `keep` يبقى بمعرّف داخلي / `anon` صف الحساب نفسه).
منها وحدها يُبنى: **تصدير البيانات**، و**محو الحساب**، و**سجل أنشطة المعالجة** العام. أي جدول جديد فيه بيانات شخصية
يُضاف سطراً واحداً هنا. الجداول غير الموجودة (مراحل أخرى لم تُدمج بعد) تُتخطّى تلقائياً.

## 1. تقرير الشفافية الدوري
- مهمة مجدولة مؤجّرة (`compliance.transparency` كل 6 ساعات عبر `ctx.scheduler`) تصدر تقرير **الشهر** و**الربع** المنتهيين إن لم يوجدا (لا تعيد التوليد).
- المحتوى أرقام مجمّعة فقط: البلاغات (حسب النوع والنتيجة، الوسيط بالساعات حتى القرار)، القرارات (وما أُلغي بعد استئناف)، الاستئنافات،
  إجراءات مشرفي المجتمعات (ومنها الآلية)، الحسابات الموقوفة/المعادة، طلبات البيانات.
- **إخفاء الأعداد الصغيرة**: أي تصنيف بين 1 و`TRANSPARENCY_MIN_COUNT-1` يظهر `<3` (الافتراضي 3)، والمجاميع دقيقة.
- لا يُنشر تقرير لفترة لم تنتهِ. الإدارة تستطيع إعادة الإصدار (`POST /api/admin/transparency/generate`).
- عام: `GET /api/transparency`، `GET /api/transparency/:period`، وصفحة مقروءة بلا JavaScript على `/transparency` و`/transparency/2026-09`.
- **غير مغطّى:** طلبات الجهات الحكومية لا يسجّلها النظام آلياً؛ التقرير يقول ذلك صراحةً.

## 2. حالة البلاغ للمبلّغ
- `GET /api/me/reports` و`/api/me/reports/:id`: خط زمني (استلمنا ← قيد المراجعة/تمت ← القرار ← «أُعيدت مراجعة القرار» إن قُبل استئناف صاحب المحتوى).
- لا يُكشف للمبلّغ نص المحتوى المحذوف ولا هوية صاحبه ولا تفاصيل استئنافه.
- الإشعار (`report_update`) يُرسل مرة واحدة لكل حالة عبر خدمة الإشعارات الحالية؛ جدول `report_updates` هو سجل «مرة واحدة».
  الإزالة تُلتقط فوراً من حدث `CONTENT_REMOVED`؛ «لا مخالفة» تلتقطها مزامنة كل دقيقتين (أو فوراً إن أُضيف `REPORT_RESOLVED`، انظر INTEGRATION.md).
- القرارات الأقدم من 72 ساعة (`COMPLIANCE_REPORT_BACKFILL_HOURS`) تُسجَّل دون إشعار، حتى لا يتلقى المستخدمون سيلاً من الإشعارات القديمة عند أول تشغيل.

## 3. طلبات أصحاب البيانات
| الحق | التنفيذ |
|---|---|
| الاطلاع والحصول على نسخة | `GET /api/me/privacy/export?format=json|zip` — ZIP يحتوي README عربي، `meta.json` (مع سجل المعالجة لكل نوع)، ملف لكل جدول، وملفات الوسائط حتى `COMPLIANCE_EXPORT_MEDIA_MAX_MB` (25). تُستبعد كلمات المرور والرموز والمفاتيح الخاصة ورسائل الآخرين. تهدئة 5 دقائق (`COMPLIANCE_EXPORT_COOLDOWN_S`). كل تصدير يُسجَّل طلباً مكتملاً. |
| الحذف | `POST /api/me/privacy/deletion` (كلمة المرور + كتابة «حذف») يجدول الحذف بعد مهلة `COMPLIANCE_DELETION_GRACE_DAYS` (30). `DELETE` نفس المسار يلغيه. مهمة `compliance.deletions` (كل 10 دقائق) تنفّذ المستحق. |
| التصحيح / الاعتراض / التقييد / سؤال | `POST /api/me/privacy/requests` → طابور الإدارة مع مهلة 30 يوماً وتمديد واحد 30 يوماً مع سبب يُبلَّغ للمستخدم. |
| سحب الموافقة | `PUT /api/me/consents` |

**ماذا يفعل المحو (`eraseUser`):** يحذف الجلسات والأجهزة والمفاتيح والإعدادات والتفاعلات والمتابعات والمسودات والإشعارات وسجل البحث…؛
يمسح نص المنشورات والتعليقات والرسائل المرسلة (تبقى المعرّفات حتى لا تنكسر السلاسل والعدادات)؛ يستبدل الاسم بـ«مستخدم محذوف» ومعرّف
`deleted_xxxx` ويمسح البريد وPi وكلمة المرور والصورة؛ يضع `status='deleted'` فلا يمكن الدخول. تبقى قرارات الإشراف والبلاغات والموافقات
وطلبات البيانات ومدفوعات Pi مرتبطة بمعرّف داخلي فقط (إثبات امتثال وسلامة). عضويات «المالك» تبقى ليظل المجتمع قابلاً للإدارة.
**ملفات الوسائط لا تُحذف** إلا مع `COMPLIANCE_DELETE_MEDIA_BLOBS=1` (تُعلَّم صفوفها `deleted` فقط). حسابات الإدارة لا تُحذف ذاتياً.
كل خطوة تُسجَّل في `dsr_requests.meta.steps`، والفشل يعيد الطلب إلى «مجدول» مع `lastError`.

**تبسيطات صريحة:** خلال مهلة السماح يبقى الحساب ظاهراً وفعّالاً (مع شريط تنبيه وإمكانية التراجع)؛ الملفات المتعددة لفيديو HLS لا تُحذف حتى مع التفعيل (يُحذف الملف الأصلي فقط)؛
نسخ المحتوى في النسخ الاحتياطية المشفّرة تبقى حتى تدوير النسخ الاحتياطية.

## 4. سياسة الاحتفاظ الآلية
- القواعد في `RETENTION` (أحداث الاستخدام 395 يوماً، الإشعارات المقروءة 180 وكلها 365، سجل البحث 180، المشاهدات 180، إشارات التفاعل 365،
  أخطاء الواجهة وقياسات الأداء وسجل التوصيل 90، سجل البريد 365، رموز البريد المنتهية 30، الأجهزة غير المستخدمة 400،
  فصل البلاغات المبتوت فيها منذ سنتين عن هوية المبلّغ). الإدارة تعدّل المدة/التفعيل لكل نوع (`PUT /api/admin/retention/:type`).
- **وضع المعاينة افتراضياً في كل البيئات بما فيها الإنتاج**: المهمة اليومية `compliance.retention` تحسب ما كان سيُحذف وتسجّله في `retention_runs`.
  الحذف الفعلي فقط مع `RETENTION_ENFORCE=1`. الحذف على دفعات (`RETENTION_BATCH`، 5000) بمفتاح أساسي.
- **ملفات الوسائط**: قاعدة `media_blobs` معطّلة افتراضياً، وحتى عند تفعيلها لا تحذف شيئاً دون `RETENTION_MEDIA_BLOBS=1`؛ تحذف فقط ملفات وسائط صفوفها `deleted` ثم تعلّمها `purged`.
- **مستثنى دائماً**: سجل التدقيق (سلسلة بصمات)، القرارات والاستئنافات، الموافقات وطلبات البيانات، سجل حوادث التسرّب.

## 5. دعم نظام حماية البيانات الشخصية
- **الأغراض والأساس** (`PURPOSES`): الخدمة (ضرورية)، الأمان والإشراف (مصلحة مشروعة)، الالتزامات النظامية، وثلاثة بالموافقة يمكن سحبها:
  التخصيص، الإحصاءات، الرسائل التعريفية (الأخيرة معطّلة افتراضياً؛ التسويق المباشر بموافقة مسبقة).
- **سجل الموافقات** `consents` إلحاقي (لا تعديل ولا حذف): الغرض، القيمة، الإصدار، المصدر، الوقت. قبول الشروط يُسجَّل بإصدارها.
- **تطبيق الموافقة فعلياً**: `ctx.track` يُغلَّف فلا تُسجَّل أحداث استخدام منسوبة لمستخدم سحب موافقة الإحصاءات؛ سحب «الرسائل التعريفية» يوقف الملخص الأسبوعي.
  للتخصيص (`engagement_signals`) والمشاهدات (`post_views`) يوجد خطّاف `compliance.hasConsent(uid, purpose)` بمقتطفات جاهزة في INTEGRATION.md (لم تُعدَّل ملفاتهم).
- **سجل أنشطة المعالجة**: `GET /api/privacy/register` وصفحة `#/policies/register` (الأغراض، الفئات، المدد، المستلمون، نقاط الحقوق).
- **سجل حوادث التسرّب** (إدارة): إنشاء/تحديث/ملاحظات/إبلاغ المتأثرين بإشعار أمني، مع ساعة 72 ساعة من وقت العلم حتى إبلاغ الجهة المختصة
  (`ok / soon / overdue / done`؛ «لا يلزم» للخطورة المنخفضة). الإبلاغ نفسه يتم يدوياً عبر المنصة الوطنية لحوكمة البيانات؛ الأداة تسجّل الوقت فقط.
- مهلة الرد على الطلبات 30 يوماً قابلة للتمديد 30 يوماً مرة واحدة مع إبلاغ صاحب الطلب بالسبب.

المراجع (للفريق، لا للاعتماد القانوني): اللائحة التنفيذية لنظام حماية البيانات الشخصية — سدايا
(https://sdaia.gov.sa/en/Research/Documents/ExecutiveRegulations.pdf)، ودليل إجراءات حوادث تسرّب البيانات الشخصية
(https://sdaia.gov.sa/en/SDAIA/about/Documents/PersonalDataBreachIncidents.pdf).

## 6–7. الشروط والخصوصية بلغة واضحة، وصفحة سياسات مقروءة
- ثلاث وثائق: الشروط، الخصوصية، مدد الاحتفاظ (الأخيرة تُولَّد من القواعد الفعلية فلا تتعارض معها). كل وثيقة: «باختصار» في الأعلى، جمل قصيرة، قسم لكل فكرة.
- الحقائق المرتبطة بالتشغيل تأتي من البيئة فلا يدّعي النص ما ليس صحيحاً: `COMPLIANCE_CONTROLLER_NAME`، `COMPLIANCE_CONTACT_EMAIL`،
  `COMPLIANCE_DPO_EMAIL`، `COMPLIANCE_HOSTING_REGION` (بدونه يقول النص إن التخزين قد يكون خارج المملكة مع تطبيق ضمانات النقل).
- داخل التطبيق: `#/policies` و`#/policies/:slug` (ملخص بارز، فهرس ينقل التركيز، عرض سطر ≤ 68 حرفاً، تباين جيد في الوضعين).
- خارج التطبيق: `/legal/terms`، `/legal/privacy`، `/legal/retention` صفحات HTML خفيفة بلا JavaScript (رابط تخطٍّ، عناوين مرتبطة، وضع داكن).

## 8. سجل قرارات الحساب
`GET /api/me/account-log` يجمع: قرارات فريق المنصة (`decisions`) مع حالة الاستئناف وزر الاستئناف (مرة لكل قرار، عبر `/api/appeals` الحالي)،
وإجراءات مشرفي المجتمعات بحق المستخدم (`mod_actions`: حذف، رفض، إنذار، كتم، حظر، رفض آلي — دون ملاحظات المشرفين الخاصة)، وإيقاف الحساب
وإعادة تفعيله من سجل التدقيق. قرارات المجتمعات تُستأنف لدى مشرفي المجتمع (رابط لصفحته). المراحل الأخرى تضيف مصادرها عبر
`compliance.registerDecisionSource(async uid => [...])`. المسار القديم `#/decisions` يعرض السجل الجديد عند الاتصال.

## متغيرات البيئة (كلها اختيارية)
| المتغير | الافتراضي | المعنى |
|---|---|---|
| `COMPLIANCE_JOBS` | `1` | `0` يوقف المهام الأربع |
| `COMPLIANCE_DELETION_GRACE_DAYS` | `30` | مهلة التراجع عن الحذف (0–90) |
| `COMPLIANCE_DELETE_MEDIA_BLOBS` | `0` | `1` يحذف ملفات وسائط الحساب عند محوه |
| `COMPLIANCE_EXPORT_COOLDOWN_S` | `300` | أقل فاصل بين تصديرين |
| `COMPLIANCE_EXPORT_MEDIA_MAX_MB` | `25` | حد الوسائط داخل ZIP |
| `COMPLIANCE_REPORT_BACKFILL_HOURS` | `72` | القرارات الأقدم تُسجَّل دون إشعار |
| `TRANSPARENCY_MIN_COUNT` | `3` | عتبة إخفاء الأعداد الصغيرة |
| `RETENTION_ENFORCE` | `0` | `1` يسمح بالحذف الفعلي (وإلا معاينة فقط) |
| `RETENTION_MEDIA_BLOBS` | `0` | `1` يسمح لقاعدة `media_blobs` بحذف الملفات |
| `RETENTION_BATCH` | `5000` | حجم دفعة الحذف |
| `COMPLIANCE_CONTROLLER_NAME` / `_CONTACT_EMAIL` / `_DPO_EMAIL` / `_HOSTING_REGION` | — | حقائق تظهر في النصوص |
